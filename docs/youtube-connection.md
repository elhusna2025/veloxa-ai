# Koneksi kanal YouTube di Veloxa

Koneksi YouTube memiliki dua tahap terpisah. Tahap pertama memberi izin baca metadata kanal, menampilkan pilihan, dan menyimpan satu kanal yang dikonfirmasi pemilik untuk setiap bisnis. Studio unggah file menggunakan izin kedua yang mencakup baca dan upload; pemilik harus mengonfirmasi secara eksplisit bahwa izin itu berlaku pada channel yang sama dengan koneksi tersimpan. Callback Google yang terdaftar tetap `/api/veloxa/youtube/callback`. Secret OAuth, token, dan URL sesi provider hanya berada di server. Dokumen ini menjelaskan kontrak dan konfigurasi, bukan bukti pengujian live.

## Persiapan Google Cloud Console

1. Aktifkan **YouTube Data API v3** di proyek Google Cloud yang akan dipakai untuk OAuth. Buat OAuth Client ID bertipe **Web application**. [Panduan otorisasi YouTube](https://developers.google.com/youtube/data/guides/authentication)
2. Lengkapi Google Auth Platform: identitas aplikasi dan kontak, audiens, domain yang berwenang, tautan kebijakan privasi, dan pengaturan akses data. Persetujuan koneksi tersimpan memakai scope `https://www.googleapis.com/auth/youtube.readonly`. Studio meminta persetujuan terpisah dengan scope baca tersebut dan `https://www.googleapis.com/auth/youtube.upload`; jangan menganggap persetujuan baca sudah memberi izin upload. Jika audiens eksternal masih **Testing**, masukkan akun penguji yang mengelola kanal. Refresh token aplikasi eksternal dalam Testing dengan scope YouTube berlaku tujuh hari. [Masa berlaku token Google OAuth](https://developers.google.com/identity/protocols/oauth2#expiration)
3. Tambahkan **Authorized redirect URI** berupa origin HTTPS aplikasi Veloxa, diikuti `/api/veloxa/youtube/callback` tanpa garis miring akhir. Nilainya harus cocok persis dengan `YOUTUBE_REDIRECT_URI`. Jangan tambahkan query, fragmen, atau kredensial. Gunakan origin HTTPS yang sama untuk memulai OAuth agar browser mengirim cookie host-only pada callback. Veloxa mewajibkan HTTPS untuk alur ini. [OAuth untuk aplikasi server web](https://developers.google.com/identity/protocols/oauth2/web-server)
4. Sebelum akses publik, tuntaskan verifikasi merek, domain, dan scope sensitif sesuai persyaratan Google untuk audiens aplikasi. Publikasi nantinya memerlukan persetujuan tambahan secara inkremental dan pemenuhan persyaratan Google yang berlaku. [Verifikasi scope sensitif](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification)

## Variabel lingkungan server

| Variabel | Persyaratan |
| --- | --- |
| `YOUTUBE_OAUTH_ENABLED` | Harus bernilai `true` untuk mengizinkan consent baru. |
| `YOUTUBE_OAUTH_ALLOWED_WORKSPACE_IDS` | ID workspace Veloxa yang diizinkan, dipisahkan koma. Daftar kosong, entri tidak valid, atau wildcard menonaktifkan consent. |
| `YOUTUBE_CLIENT_ID` | Client ID aplikasi web dari Google Auth Platform. |
| `YOUTUBE_CLIENT_SECRET` | Secret OAuth aplikasi web. |
| `YOUTUBE_REDIRECT_URI` | URL callback HTTPS terdaftar dengan path persis sebagaimana dijelaskan di atas. |
| `YOUTUBE_TOKEN_ENCRYPTION_KEY` | Kunci acak 32 byte dalam format Base64 standar kanonis dengan padding, bukan Base64URL. |
| `YOUTUBE_UPLOAD_STORAGE_RETENTION_READY` | Atur ke `true` hanya setelah aturan lifecycle bucket disetujui dan terverifikasi. Nilai kosong atau selain `true` menolak operasi unggah baru dengan `503 youtube_upload_storage_not_ready`. |

Simpan variabel di pengelola konfigurasi server. Jangan menambahkan awalan `NEXT_PUBLIC_`, menyalin nilai ke repositori, atau mencatat kode OAuth, parameter callback, isi respons provider, maupun token dalam log aplikasi atau akses. Perubahan konfigurasi OAuth membatalkan consent tertunda. Koneksi lama yang tidak lagi cocok ditampilkan sebagai `reconnect_required` sampai pemilik mengonfirmasi grant baru. Pengaturan aktivasi unggah file terpisah dari identitas konfigurasi OAuth.

Untuk uji terbatas, masukkan hanya ID workspace yang disetujui. Jika workspace tidak tercantum, daftar menampilkan `configured:false` tanpa opsi kanal tertunda, permintaan mulai dan simpan menerima `503 youtube_not_configured`, dan callback gagal sebelum pertukaran token. Pemilik tetap dapat memutuskan koneksi tersimpan secara lokal.

## Kontrak backend untuk integrasi UI

Semua path berada di `/api/veloxa/youtube`. `workspaceId` dan `businessId` wajib diisi pada setiap operasi aplikasi; gunakan `primary` atau ID bisnis `b_UUID` yang benar-benar ada. Endpoint selain callback menggunakan sesi Firebase Veloxa melalui header `Authorization: Bearer …`.

| Endpoint | Perilaku |
| --- | --- |
| `POST /start` | Pemilik workspace mengirim JSON `{workspaceId,businessId,startRevision}` dengan versi dari GET terakhir. Server membandingkan versi secara transaksional; permintaan lama mendapat 409 tanpa mengubah consent yang lebih baru. Respons `{ok:true,url}` memulai consent Google di browser yang sama. |
| `GET /callback` | Memeriksa cookie, state sekali pakai, PKCE, pemilik, serta generasi bisnis. Mengalihkan dengan 303 ke origin terkonfigurasi saja: `/?youtube=authorized` jika pilihan kanal tersedia, atau `/?youtube=failed` bila tidak. Tanpa origin callback yang valid, respons gagal tanpa pengalihan. `authorized` belum berarti kanal tersimpan. |
| `GET /accounts?workspaceId=…&businessId=…` | Akses workspace yang sah menerima `{ok:true,configured,startRevision,connection,channels,authorizationId?}`. `startRevision` adalah bilangan bulat aman nonnegatif untuk memulai consent dari versi bisnis yang telah diperiksa; tersedia juga saat konfigurasi belum aktif. Koneksi berisi `channelId`, `title`, `handle`, `url`, `status`, `connectedAt` (milidetik Unix), dan `revision` untuk konfirmasi pemutusan. Nilainya `null` jika belum ada koneksi. `handle` kosong jika Google tidak mengembalikan handle. `connected` menandakan pilihan tersimpan yang cocok dengan pemilik workspace dan konfigurasi saat ini. Endpoint ini membaca status lokal. |
| `POST /connection` | Pemilik mengirim JSON `{workspaceId,businessId,authorizationId,channelId}`. Hanya kanal dalam grant tertunda yang dapat dipilih dan satu kanal tidak dapat digunakan oleh dua bisnis dalam workspace yang sama. Respons `{ok:true}` menandakan penyimpanan berhasil. |
| `DELETE /connection` | Pemilik mengirim JSON `{workspaceId,businessId,channelId,revision}` dengan kanal dan revisi dari daftar terakhir. Koneksi yang cocok dihapus bersama izin tertunda untuk bisnis tersebut dan responsnya `{ok:true}`. Jika koneksi berubah, server mengembalikan 409 dan pemilik perlu memuat ulang daftar. Jika sudah terputus, pengulangan mengembalikan `{ok:true}` dan mempertahankan izin tertunda baru. Grant Google yang dapat dipakai integrasi lain tetap berlaku. |

State dan pilihan tertunda masing-masing berlaku 10 menit. Memulai consent baru atau menghapus koneksi yang masih tersimpan membatalkan tindakan tertunda yang lebih lama di bisnis yang sama. Koneksi tersimpan diganti saat pemilik berhasil mengonfirmasi kanal baru. Server mengenkripsi access token dan refresh token bersama dengan AES-256-GCM dan mengikatnya ke workspace, bisnis, dan grant.

Cookie YouTube memiliki pengikat acak yang terpisah dari state pada URL dan nama khusus per percobaan. Server memeriksa digest pengikat tersebut secara transaksional sebelum mengonsumsi state. Callback lama hanya menghapus cookie percobaannya sendiri. Grant yang memuat scope tambahan di luar izin baca ditolak.

UI memverifikasi pasangan daftar kanal dan `authorizationId`, mengunci perubahan saat hasil permintaan belum pasti, dan memuat ulang status sebelum percobaan berikutnya. Konfirmasi pemutusan mengikat kanal serta revisi yang ditinjau; perubahan koneksi mewajibkan konfirmasi baru.

State dan otorisasi baca yang tertunda menyimpan `deleteAt` sebagai tanggal Firestore, setara dengan `expiresAt` untuk pemeriksaan aplikasi. Jangka waktu aplikasinya 10 menit. Aktifkan TTL pada collection group `_youtube_oauth_states` dan `private_youtube_authorizations`; penghapusan fisik TTL berlangsung asinkron, bukan tepat pada menit kesepuluh. Otorisasi unggah memakai collection group `_youtube_upload_oauth_states` dan `private_youtube_upload_authorizations`, juga dengan `deleteAt` dan jangka waktu aplikasi 10 menit. TTL harus dikonfigurasi pada kedua grup baru. Perubahan ini tidak mengubah perilaku state baca yang sudah ada. [Retensi TTL Firestore](https://firebase.google.com/docs/firestore/ttl)

## Studio unggah file

Studio mengunggah file video MP4, MOV (`video/quicktime`), atau WebM hingga 128 MiB. File dikirim dalam bagian 4 MiB dengan hash per bagian; server dapat melanjutkan bagian yang belum diterima pada operasi yang sama. Setiap admission baru mempunyai namespace media acak dari server, sehingga pemakaian ulang UUID setelah riwayat dihapus tidak dapat mengambil objek lama. Kemajuan menampilkan byte file yang sudah diunggah dan byte yang sudah diteruskan ke YouTube secara terpisah. Operasi tersimpan dan berlanjut di server melalui tick scheduler per menit meski tab ditutup. Permintaan dengan hasil akhir yang belum pasti harus memeriksa operasi yang sama atau menjadi `needs_review`, tidak membuat unggahan duplikat.

Privasi awal selalu **private**. Pengguna dapat memilih private, unlisted, atau public secara eksplisit setelah meninjau ringkasan. Formulir juga mencakup penandaan konten untuk anak-anak dan deklarasi media sintetis. Untuk Shorts, pratinjau kelayakan memakai durasi terukur maksimal 180 detik dan rasio tampilan terukur setelah rotasi serta sample aspect ratio; itu hanya menunjukkan kelayakan yang diperkirakan. Klasifikasi final sebagai Shorts ditentukan YouTube, bukan pemeriksaan server ini; nama file tidak menentukan format.

Upload memerlukan channel tersimpan dan grant baca+upload baru yang dikonfirmasi pengguna untuk channel yang sama. Grant tidak menerbitkan video dengan sendirinya. Operasi memerlukan konfirmasi ringkasan metadata, file, channel, dan privasi sebelum dikirim. Thumbnail khusus, pembuatan AI, serta penjadwalan belum termasuk dalam lingkup increment ini. Pemeriksaan file memakai [FFprobe yang dipatok dan diverifikasi](youtube-ffprobe.md), tanpa fallback ke pemindai Reels lama.

Jika respons final belum dapat dipastikan, gunakan **Periksa status unggahan** pada operasi yang sama. Izin Google tertunda yang telah diverifikasi untuk channel, pemilik, bisnis, dan revisi koneksi yang sama hanya boleh dipakai untuk menanyakan sesi yang sudah ada, tanpa mengirim byte atau membuka sesi baru. Konfirmasi penyimpanan grant tetap diblokir selama fence belum terselesaikan. Setelah ID video terkonfirmasi, pemilik dapat menyimpan izin pengganti dan server hanya membacakan status ID video tersebut hingga siap. Unggahan parsial yang dikonfirmasi YouTube dapat dilanjutkan pada sesi yang sama, menggunakan grant pengiriman terikat yang masih sah dan sumber yang belum kedaluwarsa.

Akses media sementara berakhir paling lambat satu hari setelah operasi dibuat. Pembersihan fisik berjalan asinkron setelah selesai atau kedaluwarsa. Sebelum setiap penulisan GCS, server menyimpan kewajiban cleanup; jika hasil penulisan tidak pasti, satu respons DELETE 404 tidak dianggap final. Semua path operasi diperiksa ulang setiap jam sepanjang masa retensi riwayat, terpisah dari cooldown pemeriksaan YouTube. Sebelum mengaktifkan unggah file, dapatkan persetujuan eksplisit dari pemilik untuk perubahan pada bucket yang dipakai aplikasi. Catat nama bucket yang disetujui. Persetujuan harus mencakup aksi lifecycle `Delete` dengan `age: 1` untuk `matchesPrefix: ["private-youtube-uploads/"]` saja. Pertahankan seluruh aturan bucket lainnya. Setelah permintaan GET metadata bucket memverifikasi aturan yang disetujui dan aturan lama, baru atur `YOUTUBE_UPLOAD_STORAGE_RETENTION_READY=true` pada server. Lifecycle menangani objek yang muncul terlambat bahkan setelah record riwayat dihapus; eksekusinya asinkron dan tidak menjanjikan penghapusan tepat pada tenggat. Riwayat normal berlaku 30 hari; hasil final yang belum pasti kemudian disimpan sebagai catatan rekonsiliasi minimum. Judul, deskripsi, nama file asli, dan daftar hash bagian dihapus setelah sweep terakhir. Binding, URI sesi terenkripsi, ukuran sumber yang diperlukan untuk pemeriksaan status, dan fence tetap tersedia tanpa mengizinkan pengiriman byte baru. Soft-delete bucket yang berlaku tujuh hari dapat menyimpan salinan sesudah penghapusan aktif. Transfer kepemilikan workspace tidak disediakan oleh produk; perubahan `ownerUid` ditolak aturan klien. Perubahan administratif di luar alur aplikasi memerlukan penanganan operator tanpa menyalin kredensial pemilik lama ke pemilik baru.

Scheduler yang sudah ada menjalankan jalur YouTube yang terpisah dan dibatasi waktu setiap menit. GET izin/riwayat/detail selalu baca saja. Setelah seluruh file diterima Veloxa, proses server dapat berlanjut ketika tab ditutup. Dokumentasi API: [videos.insert](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert), [protokol unggah resumable](https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol), [kebijakan Shorts](https://support.google.com/youtube/answer/15424877).
