# Business context isolation

One authenticated workspace retains shared billing, quota, OAuth connections and ownership. A business is an editorial context, not a separate security principal or a new subscription.

- `workspaces/{workspaceId}/business_contexts/{businessId}` is server-only. Routes enforce workspace authorization, owner-only writes, transaction-time ownership and optimistic revision checks. Every social connection can belong to at most one business. New authorizations remain unassigned until selected explicitly.
- `primary` reads the original `snapshotJson.brand`. Additional businesses use server-generated `b_<uuid>` identifiers and independent profiles. Extra profiles are never stored in the aggregated workspace snapshot, so an older client cannot erase them when syncing its snapshot. The original root brand remains the root brand while editing an additional business. All profile saves validate logo workspace/business ownership on the server. Primary profile saves additionally compare the current profile fingerprint, update only the primary brand in the latest snapshot, and return the new snapshot revision for subsequent client CAS writes.
- Before the primary assignment record exists, valid legacy draft destination IDs supply the primary business association. Display names and usernames never determine association. Malformed old identifiers are ignored. An explicit primary assignment, including an empty list, replaces this compatibility inference.
- Assets retain server-owned workspace Storage paths. Additional-business assets carry `businessId`; missing values mean primary. Lists, reference loading, palette analysis and recoverable deletion check the selected business. Existing draft renders remain intact.
- Generation resolves the saved business profile on the server, checks its fingerprint and rejects foreign destination/reference IDs before quota or AI calls. New explicit requests store business identity with the draft. Legacy singleton requests retain compatibility only before business configuration exists.
- Publication reads the draft business, not the UI selection. It checks current rules and account assignment in the quota claim and immediately before dispatch. Queued accounts moved to another business fail individually; completed receipts are never resent. Quota remains one workspace publication for the fanout.
- The active-business preference is session-local and keyed by user and workspace. Switching clears draft inputs, selected references, review dialogs and generation messages. In-flight responses use the existing epoch guard. Unsaved profile changes block business/page switches until saved or cancelled.
- Schedule preferences are isolated planning records with exact destination IDs. Automatic scheduling is still unavailable. Meta Ads plans are paused, retain business and exact destinations, and are saved with the workspace snapshot. No ad-account connection, campaign execution, spend or optimizer is activated by this feature.

Validation uses independent business IDs, profiles, palettes, assets, schedules, destinations and drafts. Local browser fixtures do not contact Firebase, OpenAI or Meta. Live production OAuth/publication must be distinguished from local coverage.
